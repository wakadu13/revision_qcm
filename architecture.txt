ARCHITECTURE ET FONCTIONNEMENT — Révision QCM / QCR
=====================================================


VUE D'ENSEMBLE
--------------
Application écrite en Rust, compilée en un seul exécutable natif. Le code est
organisé en modules distincts selon le principe de séparation des responsabilités :

  core.rs          →  Logique métier pure (données, algorithmes, persistance)
  langues.rs       →  Module Langues : exercices, correction, sessions, stats
  fsrs.rs          →  Algorithme de répétition espacée FSRS
  bibliotheque.rs  →  Chargement de questions/ (sets classiques + langues)
  cli.rs           →  Interface en ligne de commande (+ cli/langues.rs)
  gui.rs           →  Interface graphique (egui, rendu GPU) (+ gui/langues.rs)
  math.rs          →  Moteur de rendu des formules LaTeX ($...$) pour la GUI
  paths.rs         →  Emplacement de questions/ et progression.json
  main.rs          →  Point d'entrée : choix CLI / GUI

  bin/build_dist.rs  →  Outil de génération de dist/ (binaire séparé)


DIAGRAMME DE DÉPENDANCES
-------------------------

  main.rs ──┬──→ cli.rs ──┬──→ bibliotheque.rs ──┬──→ core.rs
            │             ├──→ langues.rs        └──→ langues.rs ──┬──→ core.rs
            │             └──→ paths.rs                            └──→ fsrs.rs
            └──→ gui.rs ──┬──→ bibliotheque.rs, langues.rs, core.rs
                          ├──→ math.rs
                          └──→ paths.rs

  bin/build_dist.rs ──→ core.rs (inclus via #[path], pour lister_sets)

  core.rs, fsrs.rs et math.rs n'importent aucun autre module du projet
  (pas de dépendance circulaire).


========================================================================
MODULE core.rs — Cœur métier
========================================================================

Contient les modèles de données et toute la logique d'apprentissage.

--- Fonction normaliser_texte(s) → String ---

  Comparaison souple des réponses libres : minuscules (avec ß → ss),
  décomposition Unicode NFKD puis suppression des accents (marques
  combinantes), espaces multiples réduits à un seul.


--- Enum TypeQuestion ---

  Qcm | Qcr | Trou | Flashcard


--- Struct Question ---

Représente une question individuelle.

Champs :
  id                    String          Identifiant unique (stable, clé de progression)
  type_q                TypeQuestion
  enonce                String          Texte de la question / recto
  choix                 Vec<String>     Propositions (QCM/QCR)
  reponses              Vec<usize>      Indices (0-based) des bonnes réponses, triés
  reponses_texte        Vec<String>     Réponses acceptées (TROU)
  reponses_normalisees  Vec<String>     Idem, normalisées une fois au chargement
  verso                 String          Dos de la carte (FLASHCARD)
  explication           String          Affichée après la réponse (facultatif)

Méthodes :
  est_qcr() / est_trou() / est_flashcard()   → bool
  est_correcte(&[usize])                     → bool   sélection == bonnes réponses
  est_correcte_texte(&str)                   → bool   TROU, comparaison souple


--- Struct QuestionSet ---

Un fichier JSON chargé : un ensemble de questions sur un même thème.

Champs :
  id          String           Nom du fichier sans extension
  titre       String           Titre affiché
  description String           Description courte
  questions   Vec<Question>
  chemin      PathBuf          Chemin du fichier source
  categorie   String           Sous-dossier de questions/ (défaut : "Général")


--- Chargement ---

  lire_fichier(chemin, racine) → Result<FichierJson, String>
    Lit et analyse un fichier JSON ; déduit la catégorie (sous-dossier).

  set_depuis_json(FichierJson) → Result<QuestionSet, String>
  question_depuis_json(valeur, rang, contexte) → Result<Question, String>
    Validation, avec message clair si malformé : clés obligatoires, indices
    dans les bornes, exactement 1 réponse pour un QCM, 'reponses_texte' non
    vide pour TROU, 'verso' pour FLASHCARD… (réutilisé par le module Langues
    pour ses exercices de grammaire).

  lister_sets(dossier) → Vec<PathBuf>
    Fichiers .json du dossier et de ses sous-dossiers, triés.

  traiter_en_parallele(dossier, f) → Vec<T>
    Applique f à chaque fichier EN PARALLÈLE (un lot de fichiers par cœur
    via std::thread::scope), résultats dans l'ordre de lister_sets.

  categories(sets) → Vec<String>   Catégories distinctes, triées.


--- Struct Progression ---

Persistance et exploitation de l'historique des réponses.
Implémente l'algorithme de révision espacée de Leitner.

Stockage : progression.json (format identique à l'ancienne version Python)
  {
    "set_id": {
      "question_id": {
        "boite": int (0–5),
        "vues": int,
        "correctes": int,
        "derniere_revision": "2026-06-17T10:00:00" | null,
        "derniere_correcte": bool | null,
        // module Langues uniquement (absents sinon) :
        "stabilite": float, "difficulte": float,
        "echeance": "2026-06-20T10:00:00", "decouverte": "...", "oublis": int
      }
    }
  }
En mémoire : IndexMap<String, IndexMap<String, StatsQuestion>> (ordre des
clés conservé) ; les dates sont converties en NaiveDateTime une seule fois
à la lecture.

Méthodes principales :
  new(chemin)
    Charge le fichier s'il existe ; fichier absent ou corrompu → vide.

  enregistrer_reponse(set_id, q_id, correcte)
    Met à jour les stats et ajuste la boîte de Leitner :
      - Bonne réponse    → boite = min(5, boite + 1)
      - Mauvaise réponse → boite = max(0, boite - 1)

  est_a_reviser(set_id, q_id) → bool
    Vrai si la question n'a jamais été vue OU si l'intervalle est écoulé.
    Intervalles (jours) : boite 0→0, 1→1, 2→3, 3→7, 4→14, 5→30

  priorite(set_id, q_id) → (bool, u8, Option<date>)
    Clé de tri : (pas à réviser ?, boite, date dernière révision)
    → priorise les plus urgentes et les moins maîtrisées.

  questions_a_reviser(sets) → Vec<(Arc<QuestionSet>, usize)>
    Toutes les questions à réviser, tous sets confondus, triées par priorité
    (tri stable : à égalité, l'ordre des sets est conservé).

  resume_set(qset) → Resume
    total, rencontrees, a_reviser, precision, repartition, pct_maitrise

  sauvegarder()
    Écriture ATOMIQUE : progression.json.tmp puis renommage — une coupure
    pendant l'écriture ne peut pas corrompre le fichier.

  reinitialiser_set(set_id)
    Supprime toutes les données d'un set.

MODULE bibliotheque.rs — Chargement de questions/
========================================================================

  charger(dossier) → Bibliotheque { sets, langues, erreurs }
    Lit tous les fichiers en parallèle ; un JSON avec la clé "langue" (et

========================================================================
MODULE fsrs.rs — Répétition espacée (FSRS v4.5)
========================================================================

  Chaque élément a une stabilité S (jours avant que la probabilité de
  rappel tombe à 90 %) et une difficulté D (1 à 10).
    retrievabilite(t, S) = (1 + 19/81 · t/S)^-0,5
    premiere(note)              → état initial (S et D selon la note)
    suivante(état, jours, note) → nouvel état
      - succès : S augmente d'autant plus que D est faible et que le
        souvenir était proche de l'oubli (R faible) ;
      - oubli  : S repart d'une valeur basse.
    intervalle_jours(S) = S (rétention visée : 90 %)
  Notes : ARevoir (1), Difficile (2), Bien (3), Facile (4).
  Paramètres : valeurs par défaut publiées de FSRS-4.5.


========================================================================
MODULE langues.rs — Module Langues
========================================================================

--- Modèle ---
  SetLangue    un fichier de langue : langue, titre, exercices, particules
               optionnelles, caractères spéciaux, quota de nouveautés
  Exercice     une FACETTE suivie séparément dans progression.json :
                 id (clé de suivi), entree (élément d'origine), genre
                 (Vocabulaire / Conjugaison / Grammaire), forme, détails,
                 prérequis, max_par_session
  Forme        Carte (auto-évaluée) | Saisie (réponse tapée, tolérante ou
               non, pré-remplie, tableau de conjugaison) | Choix (QCM/QCR)
               | Ordre (mots à remettre dans l'ordre)

--- Génération des facettes (set_depuis_json) ---
  vocabulaire  → {id}#rec  carte langue → français
               → {id}#prod saisie français → langue  (prérequis : #rec appris)
               → {id}#ctx  phrase de l'exemple à compléter (mot entre crochets)
  conjugaison  → {id}#{personne} : une saisie par forme (2 max par session)
  grammaire    → TROU / ORDRE / CORRECTION / QCM / QCR / FLASHCARD

--- Correction ---
  normaliser_strict : casse, espaces, apostrophes, ponctuation finale ignorés
  noter_saisie → Verdict Juste / Accents / Faute (tolérance vocabulaire :
    distance d'édition ≤ 1 dès 5 lettres, ≤ 2 dès 10) / Faux
  Verdict → note FSRS : Juste → Bien, Accents/Faute → Difficile, Faux → À revoir
  diff(saisie, attendu) : plus longue sous-séquence commune → lettres à surligner

--- Sessions ---
  construire_session(sets, prog, mode, n)
    1. révisions dues (échéance passée), les plus menacées d'oubli d'abord ;
    2. nouveautés débloquées, réparties à parts égales entre les genres,
       dans la limite du quota du jour (quota_nouveaux) ;
    3. au plus max_par_session facettes par élément ;
    4. entrelacer : chaque genre réparti uniformément sur la session.
  Mode : Quotidien | Genre(g) | PointsFaibles (oublis > 0 ou dernier échec)
  reprogrammer : un exercice raté revient 4 positions plus loin (2 fois max)
  enregistrer(prog, set, exo, note) : stats + boîte + état FSRS + échéance
    (« À revoir » → 10 min ; sinon intervalle FSRS arrondi, ≥ 1 jour)
  prevision : délai affiché sur les boutons de note

--- Statistiques ---
  resume(sets, prog) → par genre : total, nouveaux, à revoir, maîtrisés
    (S ≥ 21 j), rétention estimée ; révisions des 7 prochains jours ;
    éléments les plus souvent oubliés.


========================================================================
MODULE cli.rs — Interface ligne de commande
========================================================================

--- Module c ---
  Codes couleur ANSI (gras, faible, vert, rouge, jaune, bleu), désactivés
  automatiquement si la sortie n'est pas un terminal.

--- Fonctions d'affichage ---
  titre(texte)              Encadré bleu avec le texte
  barre_progression(pct, l) "[####----]  42.5%"
  demander(invite)          Lit une ligne ; fin d'entrée (EOF) → "q"

--- Quiz ---
  parser_selection(saisie, n) → Vec<usize>
    "AC", "a c" ou "a,c" → [0, 2] ; lettres hors plage ignorées.

  poser_question(q, numero, total) → Option<bool>
    Affiche la question selon son type (poser_choix / poser_trou /
    poser_flashcard), recueille la réponse, affiche le retour.
    Some(juste) ou None si l'utilisateur quitte.

  derouler(questions, prog) → (score, répondues)
    Boucle commune aux sessions et à la révision intelligente ;
    sauvegarde après chaque réponse (robustesse).

--- Module Langues : cli/langues.rs ---
  menu (choix de la langue, modes, statistiques, réinitialisation),
  poser (un exercice selon sa forme), lancer (déroulé de session avec
  réessais), diff_colore (lettres fausses surlignées).

--- Vérification : cli/verifier.rs ---
  verifier(chemins) : `revision_qcm --verifier <fichier | dossier>`.
  Charge chaque fichier comme l'application (set classique ou langue) ;
  ✓ + résumé, ou ✗ + message d'erreur ; avertissements : LaTeX
  (math::diagnostiquer : $ non fermé, commande inconnue), id en double,
  TROU sans « ___ », QCR entièrement juste, traduction de vocabulaire
  partagée, exemple sans [crochets], phrase à ordonner de plus de 9 mots.
  Code de sortie 1 si un fichier est invalide.
  Un test vérifie que l'exemple JSON de chaque prompt de prompts_ia/
  passe sans erreur ni avertissement.

--- Menus ---
  choisir_categorie / choisir_set, menu_session, menu_revision_intelligente,
  menu_statistiques, menu_reinitialiser, main (boucle principale),
  demander_interface (menu de choix CLI/GUI au lancement).


========================================================================
MODULE gui.rs — Interface graphique (egui / eframe)
========================================================================

Mode « immédiat » : à chaque frame, l'écran courant est entièrement décrit
à partir de l'état ; egui ne redessine que sur événement (clavier, souris,
redimensionnement) → 0 % CPU au repos. Rendu OpenGL (glow).

--- État : struct RevisionGui ---
  prog        Progression
  sets        Vec<Arc<QuestionSet>>   Rechargés à chaque retour au menu
                                      (modification des JSON à chaud)
  ecran       Ecran                   Écran affiché
  dialogue    Option<Dialogue>        Fenêtre modale ouverte, s'il y en a une

--- enum Ecran ---
  MenuPrincipal, Categories, SetsCategorie, ModeSession,
  Quiz(Quiz), Resultat, Statistiques,
  Langues, LangueMenu, QuizLangue(QuizLangue), StatsLangue (gui/langues.rs)

--- enum Dialogue (fenêtres modales) ---
  Info       message + OK (Entrée/Échap)
  Nombre     saisie du nombre de questions (valeur proposée présélectionnée)
  Confirmer  Oui (O/Entrée) / Non (N/Échap) : réinitialisation, quitter le quiz

Tant qu'un dialogue est ouvert, le clavier ne pilote plus l'écran dessous.

--- struct Quiz : moteur commun (session simple ET révision intelligente) ---
  paires     Vec<(Arc<QuestionSet>, usize)>  Peut mélanger plusieurs sets
  index, score, selection, repondu, revele, correcte, saisie

  ecran_quiz() : lit le clavier → action (Basculer, Valider, Suivante,
  Reveler, Repondre, Quitter), dessine l'écran, puis applique l'action
  (enregistrement + sauvegarde de la progression).
  Les lettres sont lues via les événements texte : elles suivent la
  disposition du clavier (AZERTY/QWERTY).

--- Module Langues : gui/langues.rs ---
  QuizLangue : file d'ExoSession, état de l'exercice courant (saisie,
  sélection, mots placés, verdict, note). Le clavier et les clics donnent
  une action (Valider, Noter, Placer, Retirer, Suivante, Facile, Quitter)
  appliquée en fin de frame ; la révision est enregistrée en quittant
  l'exercice (la touche F peut encore la passer en « Facile »).
  Boutons de note avec le délai prévu, tableau de conjugaison surligné,
  réponse attendue avec les lettres fausses soulignées, boutons de
  caractères spéciaux insérés au curseur.

--- Widgets ---
  liste_nav     Liste navigable ↑↓ / Début / Fin / Entrée / Échap / clic
  carte_choix   Choix de QCM/QCR : lettre + texte riche (formules), cliquable
  barre         Barre de progression arrondie
  bouton, petit_bouton

--- Thème et polices ---
  Palette Catppuccin Mocha. Police DejaVu Sans (et Bold) embarquée dans
  l'exécutable : couvre le grec et les symboles mathématiques.


========================================================================
MODULE math.rs — Rendu des formules LaTeX
========================================================================

Mini-moteur inspiré de TeX, sans dépendance externe.

1. ANALYSE
   analyser_texte(texte) → Vec<Segment>
     Découpe le texte en Texte / Formule sur les « $ » non échappés
     (nombre impair de $ → tout est du texte). Résultat mis en cache.
   Analyseur::liste() → Vec<Noeud>
     Arbre : Sym (symbole + classe TeX), Texte, Groupe, Frac, Racine,
     Scripts (indices/exposants), GrandOp (∑ ∫ lim log…), Delims
     (\left…\right), Espace, XFleche, Accent, Pile (\overset…).
     Tolère un backslash doublé par erreur (« \\tau » → τ).

2. MISE EN PAGE (struct Moteur)
   Chaque nœud devient une Boite (largeur, hauteur, profondeur, éléments :
   texte, filets, traits, disques) positionnée par rapport à sa ligne de base.
   - espacement entre atomes selon la table de TeX (Ord, Op, Bin, Rel…),
     « − » unaire détecté automatiquement ;
   - fractions centrées sur l'axe mathématique, racines et délimiteurs
     dessinés en vectoriel à la bonne hauteur ;
   - italique pour les variables, avec correction d'italique.

3. PARAGRAPHE
   disposer(ui, texte, taille, largeur) → Paragraphe
     Texte et formules sont répartis en lignes ; retour à la ligne entre les
     mots, et dans une formule après une relation (=, ≈…) ou un opérateur.
   Paragraphe::peindre(painter, origine, couleur)
     Dessine le tout ; la couleur est choisie au dessin (choix sélectionné,
     correct, incorrect…) sans refaire la mise en page.


========================================================================
FLUX DE DONNÉES
========================================================================

1. DÉMARRAGE
   main.rs : choisir_interface()
     --gui / --cli, sinon GUI si pas de terminal, sinon menu de choix
     → CLI : cli::main()
     → GUI : gui::lancer_gui() → RevisionGui::new() → menu principal

2. CHARGEMENT DES QUESTIONS
   core::charger_tous_les_sets(questions/)  (en parallèle)
     → lister_sets() → charger_set() pour chaque fichier

3. SESSION DE QUIZ
   Utilisateur sélectionne → questions filtrées/mélangées → boucle :
     a. Affiche question + choix
     b. Utilisateur répond
     c. q.est_correcte(...) / q.est_correcte_texte(...) / auto-évaluation
     d. prog.enregistrer_reponse(set_id, q_id, correcte)
     e. prog.sauvegarder() → écrit progression.json (atomique)

4. RÉVISION INTELLIGENTE
   prog.questions_a_reviser(sets) → filtrage + tri par priorité
   → même boucle de quiz

5. STATISTIQUES
   prog.resume_set(qset) → Resume ; aucune modification de l'état.


========================================================================
PERSISTANCE ET EMPLACEMENTS (paths.rs)
========================================================================

  Racine des données :
    - exécutable lancé depuis target/ (cargo run) → racine du projet ;
    - sinon → dossier de l'exécutable (ex. dist/).

  progression.json
    Créé automatiquement au premier lancement. Sauvegardé après CHAQUE
    réponse. JSON lisible (indenté), UTF-8, compatible avec l'ancienne
    version Python.

  questions/**/*.json
    Fichiers statiques, jamais modifiés par le programme.
    Rechargés à chaque retour au menu principal (modifiables à chaud).


========================================================================
COMPILATION ET DISTRIBUTION
========================================================================

  cargo run --release                         Lancer l'application
  cargo run --release -- --verifier questions Vérifier des fichiers de questions
  cargo test                                  Tests unitaires
  cargo run --release --bin build_dist        Générer dist/
  cargo run --release --bin build_dist -- --windowed
                                              Idem, sans console (Windows)

  Profil release (Cargo.toml) : opt-level 3, LTO complète, codegen-units = 1,
  panic = abort, symboles retirés.
  La feature « windowed » active windows_subsystem = "windows".
